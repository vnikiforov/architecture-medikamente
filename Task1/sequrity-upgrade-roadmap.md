# Предложения по улучшению архитектуры безопасности

## 1. Меры по защите данных с использованием современных принципов

Чтобы перейти от «лоскутной» безопасности к встроенной, необходимо внедрить следующие подходы:

* **Privacy by Design (Конфиденциальность по умолчанию)**:

    * **Действие**: При проектировании новой системы (МИС) закладывать защиту данных как базовое требование, а не как опцию. Система по умолчанию должна собирать только минимум данных (см. ниже), шифровать их и предоставлять к ним доступ только строго определенным ролям.

    * **Пример**: Врач видит ФИО и историю болезни пациента. Бухгалтер видит только сумму к оплате и уникальный ID пациента (без ФИО и диагноза) для сверки платежей.

* **Data Minimization (Минимизация данных)**:

    * **Действие**: Пересмотреть все собираемые данные. Запрашивать у пациента только то, что необходимо для конкретной цели. Если для записи на прием нужны ФИО и телефон — не собирать адрес прописки и хронические заболевания до момента первого визита.

    * **Пример**: Форма на сайте для записи содержит только обязательные поля (ФИО, телефон). Расширенная медицинская анкета заполняется уже в защищенном кабинете врача или пациентом в защищенной зоне клиники.

* **Data Lineage (Линии жизни данных / Прослеживаемость)**:

    * **Действие**: Внедрить систему, которая отслеживает путь данных: откуда они пришли (пациент, лаборатория), через какие системы прошли (МИС, 1С), кто к ним обращался и когда, куда были переданы (налоговая, страховая).

    * **Пример**: Инцидент: утечка списка пациентов. При внедрениии можно за 5 минут выяснить, что вчера бухгалтер экспортировал этот список в Excel и отправил по email, нарушив политику безопасности.

## 3. Механизм тегирования данных (Data Tagging)

Тегирование (маркировка) данных — это присвоение меток каждому объекту, определяющих его критичность и правила обращения. Это основа для автоматического контроля доступа (Policy-Based Access Control).

* **Как реализовать:**

    1. **Инструменты**: Современные облачные и корпоративные хранилища (AWS S3, Azure Blob, SharePoint), СУБД (MS SQL Server, PostgreSQL с расширениями) и системы DLP (например, Solar Dozor, InfoWatch) поддерживают тегирование. При загрузке файла в систему (скан паспорта, результат анализа) ему автоматически или вручную присваивается тег.

    2. **Схема тегов**:
    * PII/PHI (Персональные/Медицинские данные) — True/False.
    * Classification (Класс секретности): Public, Internal, Confidential, Secret.
    * Data-Subject (Субъект данных): Patient, Employee, Partner.
    * Retention-Period (Срок хранения): 5-years, Indefinite.
    * Source (Источник): Reception, Laboratory, 1C.

* **Пример работы:**

    * Файл _Результат_анализа_Иванов.pdf_ при сохранении получает теги: PHI=True, Classification=Confidential, Data-Subject=Patient.

    * Система контроля доступа видит: пользователь Бухгалтер Петрова пытается открыть файл.

    * Политика безопасности гласит: Доступ к файлам с тегом Classification=Confidential и Data-Subject=Patient разрешен только для ролей Doctor и Receptionist".

    * Доступ бухгалтеру автоматически блокируется, и событие записывается в лог аудита.

## 4. Инструменты, способы и меры для обеспечения конфиденциальности

В таблице ниже представлен набор мер, закрывающих выявленные проблемные зоны, с привязкой к конкретным потокам данных на диаграмме.

|Поток данных / Зона|Проблема|Предлагаемые инструменты и меры|
|-|-|-|
|Хранилище файлов (File System)|Данные в открытом виде, нет контроля доступа к файлам.|1. Внедрение системы управления правами доступа (DRM/IRM) для Office-документов (например, Microsoft Information Protection). Файлы будут зашифрованы, и открыть их сможет только авторизованный пользователь даже после скачивания.</br>2. Настройка шифрования на уровне файловой системы (EFS/BitLocker) на сервере и рабочих станциях.</br>3. Миграция с Excel на СУБД (например, PostgreSQL или MS SQL Server) с тонким разграничением прав на уровне строк и столбцов.|
|Взаимодействие: Администратор <-> Excel файлы|Ручное внесение ПДн, риск ошибок и утечек.|1. Замена Excel на Медицинскую информационную систему (МИС).</br>2. Ввод данных через веб-формы МИС с валидацией.</br>3. Настройка автоматического аудита всех действий в МИС.|
|Взаимодействие: ККМ <-> 1С Бухгалтерия|Передача данных по OLE/TCP/IP, возможно, без шифрования.|1. Настройка шифрования каналов связи (IPsec) между сервером 1С и ККМ.</br>2. Переход на клиент-серверную версию 1С, что позволит использовать встроенные механизмы шифрования трафика между компонентами.|
|Взаимодействие: 1С Бухгалтерия <-> 1С Торговля|OLE-соединение небезопасно и ненадежно.|1. Настройка регламентированного обмена через план обмена 1С с использованием шифрования (например, через защищенные HTTP-соединения или постановку в очередь на файловом ресурсе с EFS).</br>2. Использование брокера сообщений (RabbitMQ, Kafka) для гарантированной и безопасной доставки данных.|
|Взаимодействие: Лаборатория -> Папка Registry|Передача незащищенных данных через общую папку.|1. Организация защищенного канала передачи (SFTP/FTPS или AS2) вместо открытой папки.</br>2. Автоматическая загрузка результатов из защищенного канала напрямую в МИС, минуя папку общего доступа.</br>3. Внедрение антивирусной проверки для всех загружаемых файлов.|
|Доступ к Exchange Mail Server|Письма могут содержать ПДн и передаваться в открытом виде.|1. Обязательное использование TLS для всех почтовых соединений (SMTP over TLS).</br>2. Внедрение DLP-системы (Data Loss Prevention) для сканирования исходящих писем на предмет наличия ПДн и блокировки/шифрования таких писем.</br>3. Обучение сотрудников правилам пересылки конфиденциальной информации.|
|Аутентификация|Однофакторная, риск компрометации.|1. Внедрение двухфакторной аутентификации (MFA) для доступа к любой корпоративной системе (почта, 1С, файловый сервер).</br>2. Использование единого провайдера идентификации (SSO) на базе Azure AD или другой системы.|

## Дорожная карта (Кратко)

1. _Краткосрочные меры (**0-3 мес.**)_: Внедрение MFA, настройка шифрования на сервере (BitLocker), обучение сотрудников, настройка DLP на почте.

2. _Среднесрочные меры (**3-12 мес.**)_: Выбор и внедрение МИС, перевод 1С в клиент-серверный режим, настройка защищенных каналов с лабораториями, внедрение системы тегирования данных.

3. _Долгосрочные меры (**12+ мес.**)_: Миграция всех данных из Excel в МИС и СУБД, внедрение политик Privacy by Design во все новые процессы, построение системы Data Lineage.
