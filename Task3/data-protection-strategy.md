# Стратегия защиты данных «Медикаменте»

|Данные|В чём необходимость защиты|Инструменты защиты|
|-|-|-|
|**Персональные данные (ПДн) категории «обычные»** — ФИО, дата рождения, телефон, email, адрес прописки|**• Юридическая**: ст. 13.11 КоАП РФ (штраф до 75 тыс. ₽ за утечку)</br></br>**• Репутационная**: потеря доверия при публикации в СМИ</br></br>**• Бизнес-риск**: невозможность работы без согласия субъекта ПДн|**At Rest**:</br>— Шифрование СКЗИ (ГОСТ Р 34.12-2015 «Кузнечик») в СУБД через расширения (pgcrypto)</br>— Ключи в аппаратном модуле HSM (VipNet КМ или КриптоПро CSP)</br>— Автоматическая ротация ключей каждые 90 дней</br></br>**In Transit**:</br>— TLS 1.3 для всех внешних коммуникаций</br>— mTLS для внутренних микросервисов (сертификаты на базе внутреннего УЦ)</br></br>**Контроль**:</br>— Автоматическая классификация при инжесте (тег pii)</br>— DLP-система (поиск ФИО/паспортов в незащищённых каналах)</br>— Аудит всех запросов к ПДн (неизменяемый журнал в отдельном сегменте сети)|
|**Специальные категории ПДн (медицинские данные)** — Диагнозы, анализы, заключения, хронические заболевания, данные лаборатории|**• Юридическая**: ст. 13 ФЗ-323 (медицинская тайна), ст. 7.12 КоАП (штраф до 50 тыс. ₽)</br></br>**• Этическая**: нарушение врачебной тайны = утрата лицензии клиники</br></br>**• Финансовая**: компенсации пациентам при утечке (судебная практика РФ)|**At Rest**:</br>— Двойное шифрование: на уровне СУБД + на уровне приложения (до записи в БД)</br>— Хранение ключей шифрования отдельно от данных (принцип разделения секретов)</br>— Шифрование резервных копий с уникальным ключом на каждый бэкап</br></br>**In Transit**:</br>— TLS 1.3 + дополнительное прикладное шифрование (например, через КриптоПро .NET)</br>— Ограничение TTL токенов доступа к медицинским данным (макс. 15 минут)</br></br>**Контроль**:</br>— ABAC с атрибутами: department, patient-doctor-relationship, time-window</br>— Автоматическое оповещение при доступе к данным пациента вне рабочего времени врача</br>— Watermarking (цифровые водяные знаки) для экспортируемых PDF-заключений|
|**Платёжные данные** — PAN (номер карты), CVV, срок действия|**• Регуляторная**: требования Банка России к защите платёжных данных</br></br>**• PCI DSS**: штрафы за несоответствие до $500 тыс.</br></br>**• Финансовая**: прямой ущерб от мошенничества|**At Rest**:</br>— Tokenization (замена PAN на токен при первом приёме платежа)</br>— Оригиналы хранятся только в сертифицированном платёжном шлюзе (не в системе «Медикаменте»)</br>— Шифрование остатков данных (последние 4 цифры карты) через СКЗИ</br></br>**In Transit**:</br>— PCI DSS-совместимый шлюз с поддержкой 3D Secure 2.0</br>— Изоляция платёжного трафика в отдельный сетевой сегмент (VLAN)</br></br>**Контроль**:</br>— Запрет логирования полных PAN в любых системах</br>— Автоматический поиск номеров карт в логах (регулярные выражения + сканирование)|
|**Данные учёта ТМЦ и кадров** — Инвентарные номера, закупки, зарплаты сотрудников|**• Коммерческая тайна**: раскрытие закупочных цен = конкурентное преимущество для конкурентов</br></br>**• Трудовое законодательство**: ст. 85 ТК РФ (защита кадровых данных)|**At Rest**:</br>— Шифрование на уровне СУБД (TDE для PostgreSQL/MS SQL)</br>— Разделение данных: кадры и ТМЦ — в разных БД с разными ключами шифрования</br></br>**In Transit**:</br>— TLS 1.3 для интеграции с 1С (при миграции)</br></br>**Контроль**:</br>— RBAC с принципом минимальных привилегий (кассир не видит зарплаты)</br>— Ежедневный аудит операций с изменением цен/количества ТМЦ|
|**Резервные копии и архивы** — Полные дампы БД, файловые архивы за прошлые периоды|**• Регуляторная**: ст. 17 ФЗ-152 (хранение ПДн не дольше необходимого)</br></br>**• Операционная**: утечка архива = компрометация всех исторических данных|**At Rest**:</br>— Шифрование каждого бэкапа уникальным ключом (ключ удаляется после истечения срока хранения)</br>— Хранение архивов в изолированном сегменте сети («холодное» хранилище без прямого доступа из приложения)</br>— Автоматическая анонимизация ПДн в архивах старше 5 лет</br></br>**Контроль**:</br>— Журнал доступа к бэкапам с двухфакторной аутентификацией для администраторов</br>— Регулярная проверка целостности ключей шифрования архивов|
|**Данные в процессе обработки** — Данные в памяти приложения при формировании отчётов, обучении ML-моделей|**• Технический риск**: извлечение данных из дампа памяти сервера при атаке</br></br>**• ML-риски**: реконструкция ПДн из обученной модели|**Защита**:</br>— Шифрование памяти (Intel SGX / AMD SEV для критичных операций)</br>— Использование только синтетических данных или данных с дифференциальной приватностью (ε ≤ 1.0) для обучения моделей</br>— Автоматическая очистка памяти после обработки ПДн (secure wipe)</br></br>**Контроль**:</br>— Мониторинг аномального использования памяти процессами (возможная утечка)|

## Реестр программных и аппаратных средств защиты

|Категория|Средство|Назначение|Соответствие требованиям РФ|
|-|-|-|-|
|СКЗИ|КриптоПро CSP 5.0 / VipNet CSP|Шифрование ПДн по ГОСТ Р 34.12-2015|Сертификат ФСТЭК №1234 (пример)|
|УЦ|Удостоверяющий центр на базе КриптоПро УЦ|Выпуск сертификатов для mTLS|Аккредитация Минцифры РФ|
|HSM|VipNet КМ 2.0 / Рутокен HSM|Хранение ключей шифрования|Сертификат ФСБ|
|DLP|SearchInform DLP / InfoWatch|Обнаружение утечек ПДн в email/мессенджерах|Поддержка русскоязычных шаблонов ПДн|
|Аудит|СУБД с поддержкой Audit Log (PostgreSQL + pgAudit)|Неизменяемый журнал операций с ПДн|Сохранение логов 6+ месяцев (требование ФСТЭК)|
|Сетевая защита|Межсетевой экран с поддержкой TLS Inspection|Контроль трафика между сегментами|Сертификат ФСТЭК|
|Хранилище|СУБД с поддержкой TDE (PostgreSQL 14+ / MS SQL Server)|Прозрачное шифрование данных в БД|Поддержка ГОСТ через расширения|

## Ключевые принципы реализации

1. Шифрование по умолчанию: все ПДн шифруются при инжесте, независимо от канала поступления.
2. Разделение секретов: ключи шифрования хранятся отдельно от данных (физически или логически).
3. Автоматизация контроля: ручные проверки исключены — все процессы (ротация ключей, аудит, поиск утечек) запускаются по расписанию или триггерам.
4. Соответствие РФ: только сертифицированные СКЗИ и хранение всех ПДн на территории РФ (требование ФЗ-152, ст. 18.1).
5. Защита полного жизненного цикла: данные защищены в трёх состояниях — at rest, in transit, in use.
